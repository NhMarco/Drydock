# Desktop visual refresh — 2026-10-10

This pass follows the supplied Cinematic Amber mockup within Drydock's current native
`egui`/`eframe` interface. It changes presentation and artwork selection. Game actions, navigation
destinations, search, catalogue ordering, downloads, activation, settings, and API contracts retain
their existing implementations. No changes are required in `drydock-core`, the proxy, or deployment.

## Store

- Featured content uses a wider, responsive column. Category tabs sit directly above the hero.
- The featured game keeps its existing details action and top-seller position. A smooth scrim,
  semibold title, small introductory line, and amber button keep the title legible over bright art.
- Featured recommendations, New Releases, and Denuvo use an artwork-led grid with an outlined
  **View game** footer. The entire card still opens the existing details page. Columns adapt from
  one through six to the available width; scrolling is vertical. The existing recommendation
  limit and feed order are retained.
- Library portrait art is preferred for the near-square card image area. Header and feed images
  remain fallbacks. Long titles occupy up to two lines and expose the full name in a tooltip.
- All three grid tabs share `store_game_grid` and `store_game_card`, with a borrowed `StoreCard`
  presentation adapter for feed capsules and catalogue entries. Offscreen cards reserve layout
  space without painting or requesting artwork. The existing page scroll owns vertical overflow.
- New Releases retains the catalogue filter and Steam feed order. Denuvo retains its loading state,
  count, alphabetical order, 400-game limit, and selected-game highlight. The App ID previously
  displayed in each Denuvo row is available with the full name in the card's hover tooltip.
- Repacks, search results, and the Library retain their list structures and actions. Their
  typography and shared controls inherit the refreshed theme.
- The mockup's bookmarks, carousel controls, and **View all** action were omitted because the
  current app does not provide those interactions.

## Shared app styling

- All main page content shares the Store's 1,600-pixel maximum width through `CONTENT_WIDTH`.
  Details, Library, search results, Activation, Tools, Cloud, Settings, Help, and Downloads align
  with the Store at wide sizes. Nested page panels use the same cap; the existing minimum side
  gutters and narrow-window layouts remain in place. Details uses a single 20-pixel column gap
  so its media and sidebar fit exactly within that shared width.
- Navigation has more space, readable title-case labels, a larger search field, and the existing
  amber active underline. Narrow windows use smaller type and branding. The navigation destinations
  and live-search handler are unchanged. Inactive links no longer paint an opaque black underline.
- Page headings, prominent game titles, section labels, and common buttons use an embedded semibold
  font. Body text uses its regular weight, with the existing symbol and CJK fallbacks retained.
- Primary buttons use the brand accent with dark text; secondary controls use the sunken surface
  and a subtle border. Ordinary and split buttons share one paint helper. Enabled, disabled, hover,
  and keyboard focus states remain visible; split-button actions and menu ordering are unchanged.
- Shared panels and dialogs have consistent corner radii. The existing ambient background movement
  now fades smoothly rather than exposing the edges of large translucent circles.
- The Library, Activation, Tools, Cloud, Settings, Help, Downloads, details, login, and About screens
  inherit these changes through the existing shared theme, headings, panels, and button components.
- Every colour comes from `BRAND.palette` or a blend/opacity of those values. No palette values,
  white-label configuration keys, or OS theme behavior were changed.
- Footer messages truncate to the available pixel width so they cannot overlap Downloads on a
  narrow window. The complete status and detail remain available on hover.

## Sharper artwork

The featured **STAR WARS: Galactic Racer™** feed image was only **231×87 pixels**. Its classic
App-ID-based `library_hero.jpg` URL failed, leaving that thumbnail stretched across the banner.
Steam's current header uses a hashed asset path; its verified `header_2x.jpg` sibling is **920×430**.

The UI now reuses `HeaderResolver` and its existing `SteamStoreClient::header_image` cache to obtain
that current header. It prefers double-resolution hero/header siblings and retains ordinary and
feed images when larger versions are absent. This is presentation-only use of the existing image
pipeline: the worker pool, rate limit, cache lifetime, loader, and API implementation are unchanged.
It can issue the existing header lookup for the visible featured game or a visible card whose
sharper art is unavailable. It does not fetch full game details or hardcode one game's artwork.

`apps/drydock-desktop/src/artwork.rs` isolates the URL selection helper. It preserves the supplied
asset hash, query string, and fragment, skips already-large or unknown files, and removes duplicate
candidates. Tests cover those cases. The loader advances to a fallback only when an image fails.
Store thumbnails stay visible as a preview while a sharper candidate loads. Steam may not provide
large art for every game; those cards retain the available image rather than inventing artwork.

## Fonts and build patterns

Barlow Regular and SemiBold are embedded with `include_bytes!`, following the existing Noto CJK
font installation pattern. They require no runtime download or system font. The source is the
[Google Fonts Barlow directory](https://github.com/google/fonts/tree/main/ofl/barlow); the SIL Open
Font License is preserved in `assets/fonts/Barlow-OFL.txt`. These two files add about 208 KiB before
binary compression. Noto's existing license and font remain intact.

No Cargo dependencies, release features, build scripts, settings schema, or application startup
paths were added. The existing debug-only screenshot harness is used for native visual checks.
